# 圈子说法记录

留下一份「这个圈子的观众在说什么」。结论可以交给下一位读者核对。弹幕原文留在本地，不进这个仓库。

## 用户

要写这份记录、并交给下一位读者核对的人。文本是评论、课程论文或栏目观察。

## 场景

定稿的时候。结论要公开。播放器里的弹幕原文不能公开。工具按一条视频写出下面三件事。

## 问题

常规做法是按秒计数、词频和词云、情感正负。论文和剪辑工具都在用，并把词云写成观众的焦点。

这样写会把圈子写反。秒数、词和正负都算完，仍然没有「哪一句、是不是这个圈子」。换一批片子，旧词表会空。原文又不能公开，下一位读者核不对。

情感正负只回答喜欢还是讨厌。记录里不设这一栏。

## 价值

科研：公开论文已经把词云写成节目的焦点和主题。这份记录改的是这个写法。

开源：词表、判断规则和评测在仓库里。不接真实弹幕，用词表里的句子就能把测试跑通。真实弹幕只在运行的那台电脑上。

## 记录里的三件事

1. 卡在哪一段。从有进度的弹幕里找最密的 5 秒。这一段达到三成，才写成卡在这里。不到三成，写明最密的那段和比例，不把它说成卡点。
2. 不同写法算不算同一句。词表把写法收成一句。常规分词按字面拆开，例如「三三来迟」和「三迟但到」。
3. 是不是只有这个圈子在说。看这句在每个圈子里多少比例的视频出现过，不看弹幕条数。页面上的累计数可以比当前池更大，条数不是观众意见。

## 判断规则

这些数写死在 `shuofa/label.py`。看过结果之后不回头改。

- 至少两个圈子里，出现这句的视频比例达到 10%：哪里都在说。
- 否则，最高的那个圈子不低于 25%，其他圈子都低于 10%：只有这个圈子。
- 其余：看不准。

## 用法

```bash
pip install -r shuofa/requirements.txt
python3 -m unittest shuofa.test_shuofa
python3 -m shuofa baseline
python3 -m shuofa circle --root danmaku_out
python3 -m shuofa video --gz danmaku_out/new-sanguo/某个视频.jsonl.gz
```

`circle` 把五套当前公开池放在一起，写出 `shuofa_out/circle.json`。这个文件是统计，不是原文。`video` 用它来填写「是不是只有这个圈子」。

词表在 `shuofa/lexicons/families.json`。要加一句，加进这份表，不要改判断规则。
