## 一、作品概述

### 1. 背景与问题

做文化传播、美育和平台研究的人，想知道观众在热门传统文化视频里究竟完成了哪种接收：是在评价制作，是在补知识、发问，是在共情、自豪或回想，是在谈审美，是在辩论传承，还是产生了学习、转发和实践。热门视频的弹幕量级使人工编码不可行。通用情感正负向又对不上这十七类。

使用的人是做这项研究或复盘的学生和内容团队。场景是：先按写明的热门线列出视频，拉下播放器当前公开弹幕池，再得到可复核的计数、时间曲线和一张离线页面。不替代人工把某一条句子判成最终学术结论。

### 2. 目标、方向与形态

目标是把下面这套码表做成可复算流程。

1. 作品评价：制作认可、制作诟病、观看体验
2. 知识认知：文化符号提及、知识补证、知识疑问
3. 情感认同：古今共情、文化自豪、文化记忆
4. 审美鉴赏：传统美学褒扬、审美辨析
5. 传播思辨：传承困境探讨、古今适配讨论、文化比较
6. 传承意向：学习意愿、传播意愿、实践印证

申报方向是「开源赋能的 AI 应用创新」。形态是数据与知识工具：规则码表、字符级多标签模型、时间与符号统计、离线 HTML。可选步骤是用开源中文编码器微调同一套标签。

### 3. 核心亮点

- 十七类是多标签。一条弹幕可以同时评价制作和点名器物。占比相加允许超过 100%，页面上写明了。
- 观看体验（加载、字幕、时长）和制作质量分开。知识性纠错进知识补证，不自动写成制作诟病。
- 符号用词表，并且长名称优先，避免「清明上河图」被拆成「清明」。
- 进度曲线按视频等权，只统计不少于 30 条弹幕的片子，避免一条超长视频淹没其余。
- 字符模型专门用来暴露规则的缺口，不把规则分数说成真实弹幕上的人工一致率。
- 运行时不调用闭源模型接口。弹幕正文不进仓库。

## 二、需求分析与总体方案

### 1. 需求分析

现有做法通常是抽一小段人工编码，或把弹幕做成正负情感。前者盖不住热门视频，后者回答不了「这是在补证、在比较文化，还是想去学」。优先级是：先把十七类的边界写成可测试的操作化定义，再在全量上出分布，最后用模型指出定义还盖不住的说法。

### 2. 总体方案

```
热门线与标题条件
    → 当前公开弹幕池（本地，不入库）
    → 规则多标签 + 符号词表
    → 视频等权进度曲线、片内维度承接、5 秒问答邻近、视频内突发
    → 每万条密度、组内构成、空池、二级类抬升、停留与换维、组间残差
    → 类共现与点互信息、载体相对抬升、头部视频集中度、符号与维度、发送时刻、残差二字
    → 字符模型对照规则银标，并记下模型多标和规则独有
    → summary.json + 离线 HTML
```

可选分支：银标 jsonl 接到 `hfl/chinese-macbert-base`。

### 3. 可行性与成本

CPU 路径只依赖 Python 和 numpy。不训练大模型，不需要专用硬件。GPU 脚本是同一标签体系的后续步骤，默认检测到没有 CUDA 就退出。列清单和拉弹幕受公开接口速率限制，可以中断后续跑。

## 三、AI 技术与开源及第三方资源

### 1. AI 在哪里起作用

规则短语负责可解释的高精确编码。它单独不够：说法一换词就会漏。字符 n-gram、一对多逻辑回归用团队自写的 90 句训练，在核心句上检查这种漏法，并在难句上看它会不会误伤。真实弹幕上，模型只对照规则银标，用来量规则和模型差多远，不把这份分数当成人工金标。

有 GPU 时，`wenmai/train_gpu.py` 把同一份标签接到开源中文编码器，损失是多标签分类。这一步不在默认成绩里，避免没有 GPU 就无法复核。

### 2. 开源及第三方资源

见文末清单。运行时的模型计算发生在本机 numpy 或可选的 transformers 里，不把弹幕送到第三方生成式接口。

### 3. 自主开发与权利边界

团队写的是码表、短语与符号的边界、时间与共现统计、抽样、可视化、测试、GPU 训练脚本的数据接口，以及本报告。numpy、Python、可选的 torch / transformers / MacBERT 权重都不是团队训练出来的底座。弹幕是平台上的用户文字，只在本地读取，不作为开放数据集发布。

开发过程使用了编程代理起草代码和报告段落。核心句、难句、短语和测试是仓库里的约束；下文的分数来自本机运行 `python -m wenmai eval`，不是代理口中的数。

### 4. 融合方式

开源数值库提供可训练的线性分类器，开源编码器提供可选的上下文表示，团队的码表提供标签空间。去掉码表，模型没有这十七类；去掉模型，就只剩一份无法对照缺口的词表。页面直接画出两者的分数差别。

## 四、设计与实现

### 1. 核心功能

- `python -m wenmai eval`：自写句子上的规则与字符模型分数。
- `python danmaku/crawl.py --list-only`：按热门线列出视频。检索词中断后可从 `_partial.json` 续跑。
- `python danmaku/crawl.py`：拉当前公开池。已完成的视频会跳过。
- `python -m wenmai analyze`：写出不含原文的摘要，并在输出目录留下不入库的银标和例句。
- `python -m wenmai render`：生成单文件 HTML，浏览器直接打开。
- `python -m wenmai.train_gpu`：可选微调。

一条弹幕的规则顺序是：符号词表、制作认可（强短语或「创作方面 + 正向词」，遇拖沓、混乱等阻断词则不用组合规则）、制作诟病、观看体验、知识补证（含「不是……而是」）、知识疑问、其余短语类、文化比较的双向窗口。观看体验不把「字幕组辛苦了」收进去。

### 2. 关键实现

进度：多分 P 时用 `timeline_ms` 把前几 P 的时长接上。曲线横轴是片头到片尾的 20 等分。每个非空等分里，先算「落入该维的弹幕 / 该等分弹幕」，再对视频取平均。播放器池按六分钟一段拉全。中间段为空时仍继续往后拉，不把后面的段丢掉。

问答邻近：某一秒里的知识疑问，若同一秒到其后 5 秒内出现知识补证，这些疑问各记 1。不使用用户标识。

突发：每个视频切 10 段。某一类在一段里至少 3 条，且不低于该视频该类均值的 3 倍，记一次。视频总条数少于 6 的不记。

相对抬升：某一载体里该维占弹幕的比例，除以全库同一比例。1 是和全库一样。二级类用同一算法，页面只画该组至少 20 条、且不低于全库 1.3 倍的类。

每万条：该维条数除以全部弹幕，再乘以 10000。组内构成的分母是该组六个维度的命中次数之和。

停留：不少于 30 条弹幕的片子按 20 段看哪一维最多，停留率是下一格仍为同一维的比例。换维只列出不少于 8 次的交接。

组间残差：未编码且不是纯笑声的句子里抽二字（哈希抽样），某一组的二字比例减去其余组，再除以合并比例的标准误。功能词不参与。z 大于 2、该组至少 12 次、至少出现在 8 支视频里，并且单支不超过一半，才留下。这不是主题模型。

集中度：每一类里，贡献最多的一支视频占该类条数的比例，另附赫芬达尔指数。头部占比很高时，这个数不能当成所有热门视频的共性。

片内承接：不少于 30 条弹幕的片子按 20 段看哪一维最多，再数相邻两段从哪一维接到哪一维。

点互信息：两类一起出现的比例，除以两类各自比例的乘积，再取对数。它和 Jaccard 一起看：一个看重叠有多大，一个看是否高于偶然。

符号与维度：点到某一类符号时，同一条弹幕还落在哪些一级维。

发送时刻按东八区，已编码和未编码各自归一。弹幕模式只计滚动、顶部、底部等播放器字段。

残差：未编码、也不是纯笑声的句子里抽二字，用来看码表还缺什么，不称为主题模型。

银标抽样上，字符模型还会分开计数「模型多标」和「规则有而模型无」。这是规则和模型互相暴露缺口，不是人工一致率。

另一批未编码弹幕不进入这次训练。字符模型用团队自写句加上其余银标来训，再数这批句子里模型标出了哪些类。摘要和页面只留各类次数。这些次数不是人工金标。只有说法本身落在某一类的定义里，才补短语，并且补一条核心句，让 `python -m wenmai eval` 的核心句精确匹配仍为 1。

点名某个符号时，同一条弹幕还落在哪一维。点名本身就会落入知识认知，所以对照是所有点到符号的弹幕，不是全库。至少 20 次点名才计算。倍数不低于 1.3、且该维至少 8 条，才写成这个名字额外绑在知识认知以外的某一维上。

每一支片子单独给出占优维、六维条数、相对它所在载体的抬升、词表里点到的符号，以及当前池是否为空。空池不编造接收。

稀有类同时给出条数、出现的视频数和头部占比。没有一支片子以某一维为占优维时，页面直接写 0。稀少不解释成观众没有这个想法。

有 GPU 时，`train_gpu.py` 在训练集上按类搜索阈值，银标验证集用这组阈值，并在同一套 33 条核心句和 8 条难句上另算分数。分数旁边写明：这是对照码表，不是从弹幕里抽出来的人工金标。没有 CUDA 时脚本退出。权重不提交。打分和按类搜阈值的逻辑在没有 torch 时仍有单元测试。

3090 24GB、约 3 小时时加上 `--hours 3` 和本地弹幕池。种子 0 的 `hfl/chinese-macbert-base` 写下银标分数、核心句和难句的逐句差异、已编码弹幕相对规则的多标和漏标、同一批 1,500 条缺口的各类次数，以及输出目录里的边际清单。全量前向的 batch 按 24GB 取 256，训练 batch 仍是 16。预算内接着各跑一轮 `hfl/chinese-macbert-large` 和 `hfl/chinese-roberta-wwm-ext`，其余时间重复主模型的种子，范围写在 `budget.json`。重复种子的权重不保存。报告只采用主模型种子 0。本机没有 CUDA，这些分数还没有。

字符模型：一字、二字、三字，哈希到 32768 维，稀疏随机梯度，阈值在训练集上按类搜索。训练句与 `gold.json` 的句子不允许相同，测试会检查。

## 五、成果展示与效果验证

### 1. 怎么打开

无弹幕时：

```bash
python -m wenmai eval
```

有本地弹幕池时，按 `wenmai/README.md` 生成 `wenmai/results/index.html`。

### 2. 验证方法

- 核心句 33 条：十七类都至少出现一次，另有空标签句子，防止把「哈哈」「好看」收进六维。要求规则与标注完全一致。补进「讲得真好」「古代人也」「字幕不错」时，各加了一条核心句。
- 难句 8 条：换一种说法，用来展示规则的召回上限，不拿来充当成绩。
- 字符模型：90 句自写训练数据，同一批核心句和难句上另算分数。符号词仍不放进模型的记忆里。
- 真实弹幕：全量拉取后的计数、曲线和分组见 `summary.json`。银标对照分数只说明模型和规则是否接近。

### 3. 已经跑出来的结果

命令：`python -m wenmai eval`。随机种子固定为 0。

| 对照 | 条数 | 精确匹配 | 微平均 F1 | 宏平均 F1 |
| --- | ---: | ---: | ---: | ---: |
| 规则 · 核心句 | 33 | 1.000 | 1.000 | 1.000 |
| 规则 · 难句 | 8 | 0.000 | 0.200 | 0.111 |
| 字符模型 · 核心句 | 33 | 0.879 | 0.898 | 0.902 |
| 字符模型 · 难句 | 8 | 0.125 | 0.300 | 0.296 |

规则在核心句上没有漏，也没有多标。难句 8 条里，7 条完全没有命中设计中的类；「奶奶那辈人还会这门活」只命中了文化记忆，没有命中实践印证。难句微平均 F1 为 0.200，因为 9 个标签实例里只对上 1 个。这是码表的边界，不是全量弹幕的准确率。

字符模型在核心句上精确匹配 29/33。4 条不一致是：3 条漏了「文化符号提及」（后母戊鼎、昆曲、青铜器），1 条在「为什么这么卡」上多标了知识疑问和审美辨析，观看体验仍然标对。符号是开放词表，不放进字符模型的记忆里。难句 8 条里，模型只把「突然就懂古人了」整句对上。其余难句仍会漏掉设计中的类，或在对上的类旁边多标。这不是全量准确率。

全量计数来自 2026-10-07 对本机 `danmaku_out/tradition-hot` 的 `python -m wenmai analyze`。清单 959 支，其中 958 支已落盘，1 支（BV1zt411k7Es，《国家宝藏》第二季第 3 集）接口返回 -404，没有当前池。958 支里 394 支当前公开池是空的：页面弹幕计数仍在热门线以上，播放器里现在拉不到弹幕。有字的池合计 833,104 条。上一轮在连续两段为空时就停，片头空、后面有字的池被截掉；这一轮按计划中的每一段都拉。《舞千年》第二章当时记成 0 条，重拉后是 4,383 条。分布见附录。

有字的 564 支各是一颗星，预渲染在 `wenmai/results/starfield/`。方向是该片六维命中先开方、再归一之后投到六条固定轴上，稀有的维度仍能把星星从知识认知极拉开。大小是弹幕量的对数，颜色是占优的一级维。没有落入六维的 30 支是靠近原点的暗星。页面上同一张图可以拖动旋转。

![有字视频的六维星图，斜向](results/starfield/three-quarter.png)

全量读下来：知识认知 29,836 条，每万条 358.1 次；传播思辨 414 条，每万条 5.0 次，没有一支片子以它为占优维。传播意愿 142 条里，26.1% 来自同一支视频。点名昆曲时，同一条落到审美鉴赏的密度是其他符号点名的 13.02 倍。按有字的 564 支视频放回重抽样 1,000 次，这个倍数的区间是 6.83 到 19.60；汉服落到传播思辨的点估计是 4.84 倍，区间含 0。1,500 条规则没编码、也没拿去训练的弹幕里，字符模型另标 292 条，摘要只留各类次数。银标对照的宏平均 F1 为 0.879，验证 885 条，训练 3,731 条。分组、曲线、停留和符号表在附录。本机没有 CUDA，MacBERT 没有分数。

## 六、创新性与开放价值

### 1. 和常见做法的差别

常见弹幕分析把句子收成正负情感，或只做词频。本作品的标签空间是文化接收的十七类，并且把制作质量、观看体验、知识纠错和传承意向拆开。时间统计按视频等权，突发也在单条视频内部计算，避免头部视频决定整张图。

创新不在参数规模。创新在标签边界、可测试的操作化、以及模型和规则互相暴露错误的读法。

### 2. 开放成果

`wenmai/` 以 MIT 发布。可复用的是码表、统计流程、可视化生成和 GPU 训练脚本。不可开放的是弹幕正文、由正文抽出的银标和据此训练的权重。

### 3. 别人怎么接着用

换一组视频时，仍可用 `--bvid` 或改 `collections.json` 的检索词。十七类短语在 `wenmai/codebook.py`，改完要让 `python -m wenmai eval` 的核心句精确匹配保持为 1，否则就是把定义改破了。

### 4. 维护

页面已经把每万条密度、组内构成、空池、二级类抬升、停留换维、组间残差和六维星图画出来，并可以按一支片子读出占优维、六维构成、相对该载体的抬升、点到的符号，以及当前池是否为空。星图服务的是「这支片子的弹幕落在哪几维」，不是装饰。规则没盖住的说法只把各类次数留在摘要里；站得住的三条补进了短语和核心句，核心句精确匹配仍为 1。「老师」「好看」「哈哈」「投币」仍不收进十七类。有 3090 24GB 时，按 `--hours 3` 跑完主模型、大模型和另一种编码器的对照，报告只收回主模型种子 0 的分数。不计划把弹幕正文公开。

## 七、合规、安全与风险

### 1. 许可

Python 使用 PSF 许可，numpy 使用 BSD-3-Clause，本目录代码使用 MIT。可选的 PyTorch 使用 BSD，transformers 使用 Apache-2.0。`hfl/chinese-macbert-base` 的权重许可以 Hugging Face 上该模型卡片为准，只在使用者自己的机器上下载，不随仓库分发。

B 站播放器接口是网站服务，不是开源数据集。公开可访问不等于获得复制、训练、改编或再分发授权。因此正文、银标和权重不进入 git。

### 2. 数据与隐私

记录不含 `midHash`，不保存登录态。摘要只有计数、词表内符号和未编码句子的二字统计。写入仓库前看过这些二字，页面上出现的是「这个」「老师」「真的」「好看」这类普通词，不是完整句子。

### 3. AI 输出

规则会漏掉换了说法的句子，也会在短语过宽时误收。模型会在「为什么这么卡」这类观看体验上多标知识疑问。两者都不能当成某一条弹幕的最终编码。没有生成式接口，也就没有把用户文本送到外部模型的提示注入路径。代理生成的代码和段落已由测试和本机 `eval` 约束。

### 4. 权利边界

团队主张权利的是码表、程序和报告的表达。用户弹幕、平台接口和第三方模型权重的权利仍归原权利人。

### 5. 不适用的场景

不要用这套分数做内容处罚、作者排名或「文化自信高低」的结论。不要把难句上的低分解释成全量准确率。当前公开池会随时间变化，同一 BV 重拉可以和上次不同。

## 八、总结与展望

作品已经把十七类做成可测试的规则，并给出不依赖 GPU 的字符模型对照。核心句 33 条上规则精确匹配为 1，模型精确匹配为 0.879。难句说明换词之后两者都会漏。当前公开池 833,104 条里，38,566 条至少落入一类（4.6%）；点名文化符号远多于辩论传承。394 支热门视频的当前池是空的。页面可以按片名读出占优维、六维构成、相对该载体的抬升和点到的符号；空池写明当前池是空的。有字的 564 支里，482 支的占优维是知识认知。传播思辨有 414 条，没有一支片子以它为占优维。1,500 条规则没编码的弹幕上，字符模型另外标中 292 条，摘要只留各类次数。

下一步是在有 GPU 的环境用仓库里的脚本把银标接到 MacBERT，阈值按类搜索，并在这 33 条核心句和 8 条难句上打分。商业化不是本作品的目标。
